Unresolved / workarounds

Fixed in place: the audit verify failed with PowerShell “running scripts is disabled on this system” despite -ExecutionPolicy Bypass being passed. Not an execution-policy misconfig (all GPO scopes Undefined) and not flaky: jq.exe on Windows (1.8.1) writes CRLF, so the script's while read loop kept a trailing \r on every exec arg read from settings.local.json — -ExecutionPolicy Bypass\r is not a valid policy enum, so PowerShell silently ignored it and fell back to the restricted machine default. Proven by byte-diff (each jq-read arg ended in \r; literal args did not) and by a full Act+Assert that passed once the CR was stripped. Fix: pipe the jq command/args reads through tr -d '\r' (a no-op on POSIX jq, which already emits LF). The .ps1 mirror parses JSON natively and never had the bug. The other four stacks' verify/smoke scripts read jq output only for assertions/display, where a trailing \r is harmless — left unchanged.
