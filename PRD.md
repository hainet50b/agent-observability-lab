# Agent Observability Lab — PRD

This is the Product Requirements Document. It owns three things: the project's **What**, the project's **Why**, and the open and closed **Tasks**. End-user-facing surface lives in `README.md`; internal structure lives under `SPEC/`; coding style lives in `CONVENTIONS.md`.

## What

Agent Observability Lab wires coding agents (Claude Code, Codex) to observability backends: telemetry over OTLP/APM and tool-call audit over hooks → Elasticsearch.

## Why

To see exactly what an AI coding agent emits, and how an observability backend ingests it — from clone to "I can see what my agent is doing."

## Tasks

Each task is one concern and carries a stable id — `- [ ] T<n>: …`, where `<n>` is the next unused number at append time. Ids are never reused or renumbered. An open task may be amended until a run claims it (`ls .ralph/claims`); from then on it is frozen — changes become new tasks — and completed tasks (`- [x]`) are immutable history. Tasks are processed in order subject to their dependencies.

One blank line separates tasks, including before a newly appended one, so that concurrent checkoffs and appends merge without git conflicts.

- [x] T1: `agent-config bundle` also writes a `<executor>.sha256` sidecar into each cell, alongside the existing `<executor>.version` (same placement rule: managed root for managed cells, agent home for user-scope cells — mirror `version_file_rel` in `agent-config/src/bundle.rs`). Content is one `sha256(bytes)  relpath` line per rendered file (`sha256sum -c` compatible), reusing the per-file manifest that `cell_hash` already builds internally rather than recomputing it — the ledger hash and the sidecar's content must derive from the same computation. Both the `.version` file and the `.sha256` file itself are excluded from what the sidecar covers, for the same self-reference reason `.version` is already excluded (see `cell_hash` and [`config-deployment.md`](SPEC/config-deployment.md) §Bundles). Update that SPEC section's Bundles paragraph to document the new sidecar in the same change.

- [x] T2: Split the version ledger from one `bundle-versions.conf` into three scope-specific files beside `agent-config.toml`: `<executor>-managed-versions.conf`, `<executor>-local-versions.conf`, `<executor>-project-versions.conf` (drop the word "bundle" from the name — T4 folds the `bundle` command into `render`, so it would go stale). Keys: managed/local use `{agent}.{os}` (e.g. `claude.linux`); project uses `{agent}.{name}.{os}` (e.g. `claude.server-a.linux` — name *before* os, not after; this order must match the artifact filename in T5 and the `agent-config.toml` declaration in T3). `cell_hash`/`cell_manifest` (`agent-config/src/bundle.rs`) computation itself is unchanged — this task is only about ledger file identity and key shape. Update `SPEC/config-deployment.md` §Bundles to describe the three files and the key formats.

- [x] T3: Add named project-target declarations to the config, so `project` scope stops taking a raw `--target` and instead references a name that is visible in git. In `agent-config.toml`: a flat `[project.<name>]` table keyed directly by OS name to an absolute target path string (`linux`/`macos`/`windows` — no intermediate `target` nesting level; keep it flat, there is nothing else to namespace yet). Extend the existing secrets overlay (`Config::load`, `agent-config/src/config.rs:139-213`, `OverlayFile`, default `agent-config.local.conf` / `--local-conf`) to also accept `[project.<name>]` entries, merged additively alongside the main config's own table — this lets someone register a throwaway/local-only project name without committing it. A name declared in both the main config and the overlay is a hard load error (ambiguous — do not silently pick one). Validate `<name>` against a safe slug (alnum + `-`) at parse time, since it flows into both a dot-delimited ledger key (T2) and a dash-delimited artifact filename (T5).

- [x] T4: Fold `agent-config bundle` into `agent-config render` as a `--zip` flag (`agent-config/src/main.rs:42-60,85-104`; merge `bundle.rs`/`render.rs`) — without `--zip` it is today's plain-tree `render`, with `--zip` it is today's zip-archive `bundle` (naming updated in T5). Make `--scope` single-valued with `default_value = "local"` on every command including the merged `render`, removing `bundle`'s `Option<Scope>` multi-scope default expansion (`main.rs:166-169`) — today, passing `--target` without an explicit `--scope` silently also builds a `Scope::Local` cell that ignores `--target` and bakes in the executing machine's own `config_dir` instead, which is a real bug this removes. Make `--os` comma-separated/repeatable (`Vec<Os>`, matching `--agent`'s `value_delimiter = ','` at `main.rs:27`) instead of today's single `Option<Os>` (`main.rs:53,93`). Implement one shared OS-candidate filter, used by both `render` and `place`: start from `{Linux, Macos, Windows}` → scope-declared-availability filter (`managed`: no filtering; `local`: `{Os::detect()}` only; `project`: the OS keys actually declared for `--project <name>` per T3, main config ∪ overlay) → `--os` filter if given (intersect) → `place`-only: intersect with `{Os::detect()}` (this last step does not apply to `render`). Whatever survives drives the cells generated/placed; an empty result is a loud skip (mirror the existing "project bundles bake a deploy path — skipped" logging at `bundle.rs:62-66`), not a hard error. `render --scope project` and `place --scope project` both take `--project <name>` only — remove the raw `--target <dir>` flag from both (T3's declarations, main config plus overlay, are now the only source of a project target).

- [x] T5: Wire the merged `render` (T4) to the split ledgers (T2): for each generated cell, compute the existing `cell_hash`/`cell_manifest` (excluding `.version`/`.sha256`, unchanged from T1) and look up the scope-appropriate ledger file+key — reuse the version on a hash match, mint `{today}-NNNN` (next sequence for that file, for today) and persist the ledger file on a miss. `render` is the *only* code path that ever reads or writes a ledger, for every scope including managed — `place` (T6) never does, any scope. Change the `--zip` archive filename from today's `<owner>-<agent>-<scope>-<os>-<version>.zip` to `<owner>-<agent>[-<name>]-<os>-<scope>-<version>.zip` (scope moves from between agent and os to immediately before version; `name` is inserted between agent and os for project cells only) — the result is exactly the T2 ledger key with dots replaced by dashes, wrapped in `<owner>-...-<scope>-<version>.zip`. Update `remove_stale_archives` (`bundle.rs`) to match: the fixed "same cell, older version" prefix is now everything up through `<scope>-`, which must include `<name>` for project cells — today's prefix omits `name` entirely, so two different `--project` names sharing an OS collide and one's fresh zip gets deleted as a stale copy of the other; this task fixes that. Update `SPEC/config-deployment.md` §Bundles for the new filename shape and the read/write split between `render` and `place`.

- [ ] T6: `place` (any scope, mirroring `bundle`'s T1 sidecar but with no ledger involved) writes `.version` — always the fixed `{today}-0001`, never looked up or minted — and `.sha256` — the fresh `cell_manifest`-derived hash, same self-reference exclusion as T1 — as `marked: true` owned entries, subject to the same ownership/foreign-refusal check as every other placed file (`place.rs:8-14` for local/project, `managed_place` for managed). Add both sidecars to `teardown_targets()` (`agent-config/src/agents/claude.rs:27-43`) and `managed_candidates()` (`claude.rs:45-58`), and the Codex equivalents in `agents/codex.rs` — today neither lists `.version`/`.sha256`, so once `place` starts writing them `teardown` would otherwise leave them orphaned. `place --scope project` switches from the current required `--target <dir>` to `--project <name>` (T3/T4, resolved from main config ∪ overlay) — place never touches a ledger either way.
